# FleetFlow REST API v1

Base URL for local development: `http://127.0.0.1:5080`. The existing Vite proxy also forwards `/api` to this API. This unauthenticated application must remain local; Compose and the host development profile bind published services to loopback. No public deployment was performed.

The executable contract is [Development OpenAPI JSON](http://127.0.0.1:5080/openapi/v1.json). It includes DTO schemas, summaries, parameter bounds, response codes, and representative examples. OpenAPI is unavailable outside Development.

## JSON and validation

Send `Content-Type: application/json`. Properties use camelCase; identifiers are UUIDs. JSON enums use names (`Draft`, `Planned`, `InTransit`, `Delivered`, `Cancelled`; `Van`/`Truck`; `Available`/`Maintenance`/`Inactive`), not numeric values. Timestamps must be ISO 8601 with `Z` or an explicit offset; they are normalized to UTC on input and output. Cargo weights are decimal numbers, not formatted strings, with positive values and at most two meaningful fractional digits. Pallet count is nonnegative. Deadline must be strictly after pickup. Address countries use ISO 3166-1 alpha-2 codes.

Required properties must actually be present. Unknown JSON properties are rejected, including attempts to set `status` through shipment PUT or forge the actor. Shape/binding validation returns 400; semantic rules return 422 or a state/resource conflict 409. Field length requirements appear in the generated schemas. Read-only response fields must not be sent back indiscriminately as a write payload.

Every shipment mutation except creation requires positive `version` copied from the latest response. Successful mutations increment it once. Stale writes return 409 with `code: "stale_version"`: fetch current detail, show the change, and let the operator decide whether to retry. Do not silently overwrite with an automatically refreshed version. Driver/vehicle updates serialize through resource locks; shipment Version does not apply to those master records.

All successful shipment responses contain the saved core fields, timestamps and version. GET/list/dashboard also resolve `customerName`, `assignedDriverName` and `assignedVehiclePlateNumber` in joined SQL projections. Those nullable display labels are null on mutation responses, which report the committed command snapshot without a second racing read. A client should invalidate/refetch detail and list queries after a mutation.

## Create a shipment

The sample customer UUID below is the first fictional seeded customer. Otherwise use an ID returned by customer creation or listing. Dates are illustrative; supply the desired offset-qualified schedule.

```http
POST /api/v1/shipments
Content-Type: application/json

{
  "customerId": "00000001-0000-4000-8000-000000000001",
  "origin": { "street": "Demo Depotstrasse 1", "city": "Graz", "postcode": "8010", "countryCode": "AT" },
  "destination": { "street": "Demo Lagerweg 2", "city": "Vienna", "postcode": "1010", "countryCode": "AT" },
  "pickupWindowStartUtc": "2026-11-07T08:00:00Z",
  "deliveryDeadlineUtc": "2026-11-07T16:00:00Z",
  "weightKg": 1200.50,
  "palletCount": 3,
  "cargoDescription": "Fictional demo pallets"
}
```

The 201 response contains a generated `id`, atomic `shipmentNumber`, `status: "Draft"`, `version: 1`, UTC created/updated timestamps, null assignment/actual timestamps, and the submitted normalized fields. Location is `/api/v1/shipments/{generated-id}`. Send the returned ID in the following requests.

## Assign and complete the lifecycle

Use eligible IDs from the fleet lists; the sample IDs below are the first seeded active driver and available vehicle. Other active reservations may make a particular schedule unavailable.

```http
POST /api/v1/shipments/{id}/assign
Content-Type: application/json

{ "version": 1, "driverId": "00000002-0000-4000-8000-000000000001", "vehicleId": "00000003-0000-4000-8000-000000000001" }
```

Success keeps Draft, returns `version: 2`, assigns both resources and writes one AssignmentChanged event. Then:

```http
POST /api/v1/shipments/{id}/status
Content-Type: application/json

{ "version": 2, "status": "Planned", "reason": "Dispatch confirmed" }
```

```http
POST /api/v1/shipments/{id}/status
Content-Type: application/json

{ "version": 3, "status": "InTransit" }
```

```http
POST /api/v1/shipments/{id}/status
Content-Type: application/json

{ "version": 4, "status": "Delivered" }
```

The final response has `status: "Delivered"`, `version: 5` and server-generated actual pickup/delivery times. History has exactly five records: Created, AssignmentChanged and three StatusChanged events, with actor `local-dispatcher`. This fixed actor is supplied by the server until authentication is implemented; it is not a verified user identity.

Allowed transitions are Draft → Planned/Cancelled, Planned → InTransit/Cancelled and InTransit → Delivered. Delivered/Cancelled are terminal. Repeated commands return explicit conflicts rather than duplicate events. Planning and departure both revalidate eligibility/reservations. Draft selections do not reserve capacity. The MVP reserves one driver and one vehicle per overlapping active shipment using `[pickup, deadline)` intervals; adjacent intervals are allowed.

## Editing

Shipment PUT sends the same fields as creation plus `version`; omit all other response fields. Draft fields may change, with payload rechecked against an existing selection. Planned allows only cargoDescription to differ; all other fields must retain their current values. Other statuses are locked. Each accepted edit writes one DetailsChanged event. An unchanged edit returns 409/details_unchanged.

```json
{
  "version": 3,
  "customerId": "00000001-0000-4000-8000-000000000001",
  "origin": { "street": "Demo Depotstrasse 1", "city": "Graz", "postcode": "8010", "countryCode": "AT" },
  "destination": { "street": "Demo Lagerweg 2", "city": "Vienna", "postcode": "1010", "countryCode": "AT" },
  "pickupWindowStartUtc": "2026-11-07T08:00:00Z",
  "deliveryDeadlineUtc": "2026-11-07T16:00:00Z",
  "weightKg": 1200.50,
  "palletCount": 3,
  "cargoDescription": "Updated fictional pallet description"
}
```

## Filtering and pages

```sh
curl 'http://127.0.0.1:5080/api/v1/shipments?status=Planned&search=Graz&page=1&pageSize=20'
curl 'http://127.0.0.1:5080/api/v1/shipments?deadline=Overdue&pageSize=20'
curl 'http://127.0.0.1:5080/api/v1/shipments?deadline=DueSoon&pageSize=20'
```

Optional `status`, `customerId`, `search` and `deadline` combine using AND. Search is a case-insensitive literal substring over shipmentNumber and both cities; `%`, `_` and backslash are escaped, not interpreted as wildcards. Search is limited to 100 characters. Default shipment lists include cancelled records unless filtered by status/deadline.

Every collection, including history and master-data lists, uses this envelope:

```json
{ "items": [], "page": 1, "pageSize": 20, "totalCount": 0, "totalPages": 0 }
```

Defaults are page 1 and pageSize 20; page is bounded to 1..1000000 and pageSize to 1..100. Invalid values return 400 instead of silently clamping. Valid pages beyond available rows return empty items with the actual total count. Shipment order is createdAtUtc descending then UUID descending. History is occurredAtUtc ascending then UUID ascending for equal times. Customers sort by name/id; drivers by employeeNumber/id; vehicles by plateNumber/id. Offset pages can shift when other requests add or change data; there is no cross-request snapshot or cursor contract.

## Dashboard definitions

`GET /api/v1/dashboard/summary` returns `asOfUtc`, `totalNonCancelledShipments`, `draftShipments`, `plannedShipments`, `inTransitShipments`, `deliveredShipments`, `overdueShipments`, `dueSoonShipments`, and up to 10 `recentShipments`.

Total excludes Cancelled and includes Delivered. Overdue means deadline strictly before asOfUtc; due soon means deadline from asOfUtc through asOfUtc + 24 hours inclusive. Both exclude Delivered and Cancelled. Recent shipments include all statuses and use the shipment sort order. Counts are computed in SQL; counts and recent rows share one repeatable-read database snapshot. TimeProvider supplies a single calculation instant. Empty databases return zero counts and an empty recent list.

## Master-data write payloads

Customer creation:

```json
{ "name": "Alpenstern Demo GmbH", "contactName": "Demo Contact", "email": "demo@fleetflow.example", "phone": null }
```

Driver creation or replacement:

```json
{ "employeeNumber": "DEMO-101", "firstName": "Demo", "lastName": "Driver", "active": true, "licenseCategory": "C" }
```

Vehicle creation or replacement:

```json
{ "plateNumber": "FF-DEMO101", "type": "Truck", "maxPayloadKg": 12000, "status": "Available" }
```

Employee numbers and plates are trimmed and uppercased. Duplicates return 409. Deactivating a driver, making a vehicle unavailable, or reducing payload below an active shipment's weight returns 409/resource_in_use. These edits acquire the same resource locks used by shipment operations, so they cannot race a successful incompatible plan. License category is informational.

## Problems

Problems use `application/problem+json`, a status, safe title/detail, stable machine-readable code and traceId. Malformed/binding errors also include an `errors` dictionary with safe generic field messages; rejected values, serializer exception details, stack traces, SQL and secrets are not reflected.

```json
{
  "type": "about:blank",
  "title": "The operation could not be completed.",
  "status": 409,
  "detail": "This shipment has changed. Reload it before trying again.",
  "code": "stale_version",
  "traceId": "example-request-trace"
}
```

| Status | Examples |
| --- | --- |
| 400 | invalid_request: invalid JSON, missing required properties/version, unknown write fields, invalid enums/UUIDs, invalid pagination, offset-less timestamps |
| 404 | not_found: missing shipment, customer reference, driver or vehicle |
| 409 | stale_version, invalid_transition, assignment_required, assignment_overlap, assignment_unchanged, assignment_locked, shipment_locked, fields_locked, details_unchanged, driver_inactive, vehicle_unavailable, resource_in_use, duplicate_value |
| 422 | invalid_weight, invalid_country, invalid_schedule, invalid_pallet_count, invalid_email, vehicle_overloaded and other semantic input rules |
| 500 | unexpected_error: generic safe message; use the traceId for diagnostics |

No API command changes state if validation fails. Shipment state and its event are committed together; integration tests deliberately fail event storage to verify rollback. Unexpected failures are logged server-side and never exposed as database exceptions to clients.
